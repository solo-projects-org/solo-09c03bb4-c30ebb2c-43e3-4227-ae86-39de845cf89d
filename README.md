# 工业炉保温验收 · 温度格网交接页

用 Flask + SQLite 实现的炉衬测温方阵四叉树分区与供数交接工具。

## 它做什么

1. **上传测温方阵 CSV**：行列数相等且边长为 2 的幂（2、4、…、512）；
   格内填整数摄氏度，空白表示未测；UTF-8/GBK 编码、可选表头。
2. 填入**允许温差**后，从整张网格逐级四等分，用**最少的互不重叠方块**
   覆盖全部实测格：
   - 方块内不得含未测格；
   - 每块报最高温，块内任一读数与最高温之差不超过允许温差
     （整数温度下等价于 `max - min <= tol`）。
3. 网页按 1 基行列号**成批补测或清空**矩形区域，只重新核算包含改动格的
   四叉树节点与覆盖块。
4. **热像仪补测表对位**：补测表只含局部行列号、整数温度与用途（参照/补测），
   在网页指定的搜索区内枚举平移与 0°/90°/180°/270° 四种朝向（不做镜像），
   参照点与已有实测逐点吻合才可行；所有可行摆法给出同一组补测落点才预览，
   确认时用最新实测重核且目标格全未测才整批入库（详见下节）。
5. **下载现行供数 CSV**：块的位置、边长、温度来自同一批已生效数据；
   补测或写入失败时整笔事务回滚，旧表仍可下载。
6. 全程用 Docker Compose 启动。

## 热像仪补测表对位规则

补测表（4 列 CSV：`local_row, local_col, temp, purpose`，示例见
`examples/sample_alignment_sheet.csv`）只保留热像仪自身的局部 1 基行列号，
丢失了它在炉壁上的位置与朝向。对位流程（`app/alignment.py` 为纯算法）：

1. 网页填写**搜索区**起止行列（1 基），上传补测表；`purpose` 取“参照”
   （或 ref）与“补测”（或 fill），温度必须是整数摄氏度。
2. 系统在搜索区内枚举全部摆法：整组点（参照+补测）经一次旋转（仅
   0°/90°/180°/270°，**无镜像**）加同一平移后必须**全部落在搜索区内**；
   每个参照点落点处的已有实测温度必须与表中温度**完全相等**。
3. **补测目标格是否已测不参与摆法筛选**——已测格只在确认入库时拦截，
   不能据此排除摆法。
4. 收集全部可行摆法的补测“坐标+值”集合：
   - 所有摆法同一组落点 → 生成唯一预览（参照/补测落点、目标格现状）；
   - 存在多组不同落点 → 报歧义，不预览；
   - 无可行摆法 → 区分“点集无法整体落入搜索区”与“参照全部不吻合”说明原因。
5. **确认**在一个 `BEGIN IMMEDIATE` 事务内完成：重新解析原始补测表、
   用最新实测重新对位求解，结果仍唯一且补测坐标/值与预览完全一致、
   参照仍吻合、全部补测目标格当前未测，才复用 `apply_edits` 的增量核算
   整批写格并同步更新现行供数块；任一条件不满足则回滚，**读数与供数不变**，
   页面提示重新对位。预览期间其他补测可正常入库（写锁只在确认瞬间持有）。
6. **重传底图**（整体替换格网）会作废旧预览，要求重新预览；**只改允许温差**
   不动 cells，预览继续有效。放弃预览不写任何读数。

## 为什么块数最少

合法性可“遗传”：一个方块合法（无未测格且温差不超限），其任意子方块也合法。
因此最优覆盖就是所有**最大合法节点**——自身合法、父节点不合法的四叉树节点。
任何不重叠方块覆盖都无法跨越四叉树对齐边界，所以每个最大合法节点至少需要
一块，本方案每节点恰用一块，块数最少。`tests/` 中有小网格暴力枚举对照。

## 数据与增量核算

SQLite 表（见 `app/db.py` 建表语句）：

| 表 | 作用 |
|---|---|
| `grid` | 方阵边长与当前允许温差 |
| `cells` | 每格温度，`NULL` 表示未测 |
| `nodes` | 四叉树内部节点（size≥2）的计数、温区与合法标志 |
| `batch` | 批次，每次成功的上传/改温差/补测清空各产生一批，`is_current=1` 为现行 |
| `block_op` | 块变更日志：`base` 整套、`add` 新增、`tombstone` 作废，保留批次历史 |
| `blocks_current` | 现行块物化表，与 `block_op` 同事务维护，下载直接顺序读 |
| `alignment_preview` / `alignment_preview_point` | 当前唯一一份对位预览（搜索区、原始补测表、参照/补测落点），重传底图或重新预览时整表替换，确认成功后删除 |
| `event_log` | 操作审计 |

补测/清空的增量步骤（`db.apply_edits`）：

1. 取改动格的全部祖先节点（单格只有 log₂N 个）；
2. 自底向上只重算这些节点的统计与合法标志；
3. 自根向下收集块增量：未受影响子树整棵跳过，受影响路径按新合法性
   写 `add` / `tombstone`；块合并时用区域墓碑作废被吸收的旧块，
   块拆分时按新结构补发存活子块；
4. 全部在一个 `BEGIN IMMEDIATE` 事务内，异常回滚，旧批次与旧供数不变。

下载与页面读同一张 `blocks_current`，保证位置、边长、温度同源。

## 启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

数据存于命名卷 `furnace-data`（容器内 `/data/furnace.db`），重建容器不丢数。

## 本地开发与自测（不依赖 Docker）

环境无 pip 时可先把依赖装到项目本地目录：

```bash
python3 -m ensurepip            # 若系统提供
python3 -m pip install --target .pylibs -r requirements.txt
PYTHONPATH=.pylibs:. python3 -m unittest discover -s tests -v
PYTHONPATH=.pylibs:. FURNACE_DB=/tmp/f.db python3 -m flask --app app.wsgi run --port 8000
```

## 自测覆盖

- `tests/test_app.py`（24 个用例）：CSV 解析、四叉树覆盖与块数最少性、
  120 轮强随机补测/清空下物化表/delta/全量重建三者一致、增量只重算
  祖先节点、事务回滚、批次历史、Web 端到端。
- `tests/test_alignment.py`（36 个用例）：
  - 旋转：四朝向纯旋转无镜像（有向面积手性不变）、转四次复原、点序保持；
  - 求解：唯一摆法、90° 朝向、搜索区约束、参照温度失配/参照落点未测无解、
    点集大于搜索区、多摆法同落点可预览、不同落点报歧义；
  - **目标格已测不排除摆法**，仅确认时拦截（温度相同也拦截）；
  - 解析：表头/GBK/用途标记/重复坐标/全参照/行列与温度校验/空文件；
  - 服务层：预览落库与替换、确认后供数块与全量重建一致、无预览确认报错、
    **交错补测**占用目标格或参照读数变化时整批回滚（读数与供数不变、预览保留）、
    多点部分占用整批拒绝、重传底图作废预览、改温差保留预览、放弃预览；
  - Web 端到端：预览/确认/放弃、歧义与坏表不污染下载、交错占用被拒、无底图拦截。

运行：

```bash
PYTHONPATH=.pylibs:. python3 -m unittest tests.test_app tests.test_alignment -v
```

## 已知边界与取舍

- 边长上限 512、温度合理区间 `[-100, 3000] ℃`，在 `app/csvutil.py` 可调。
- 大网格（512）全量上传约 3–4 秒、20 万块下载约 1 秒（流式输出，内存恒定）；
  单格/小批量增量编辑为毫秒级。
- 改允许温差是全局重算，会以整套 `base` 块重建并截断旧 delta 链；
  补测/清空才走局部增量，历史 delta 连续保留。
- 界面网格视图对大于 32 行/列的方阵只预览左上角，完整数据以批量操作和
  下载 CSV 为准。
